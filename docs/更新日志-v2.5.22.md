# 一加16提权越狱 v2.5.22 更新日志（修复加载后收尾必失败导致的“卡死/重启”）

**作者：星苒鸭 · github.com/xingranya · xran.uk**

## 根因（必发，不是偶发）
v2.5.17 起接入上游 run.sh 链（loader2/w2）时，我们漏掉了加载器要求的引导文件路径：

- 加载器 `cred.bin` 会固定从 **/data/local/tmp/ksud_official** 读取 ksud，并安装到 /data/adb/ksud
- 我们只投放了 `/data/local/tmp/ksud_sukisu`，没有投放 `ksud_official`
- 结果：LKM 加载成功、模块 Live，但 /system/bin/su 不存在
- 收尾 `ksu_grant` 失败、`su -c` 失败 → 管理器没初始化、安全组件没停用
- ColorOS 检测到模块 → 弹窗并 15 秒重启（表现为“加载完 30 秒内卡死”）

## v2.5.22 修复
1. 加载前同时把同版本 ksud 投放到 `/data/local/tmp/ksud_official`（加载器固定路径），并保留各管理器自己的副本给收尾使用
2. ColorOS 反 root 守卫（`com.oplus.exsystemservice`）改为：
   - 加载前先用 shell 停用 + force-stop，避免加载窗口内触发 15 秒重启
   - 收尾阶段拿到 su 后再停用/清理一次
   - 流程完成后恢复服务
3. 第二个拦截：`oplus_secure_guard_new` / `oplus_secure_common` 内核保护模块，收到 su 后动态 rmmod，真机确认已从 /proc/modules 消失
4. 加载阶段保留完整实时日志（perm/writer 的 attempt、slab、landed 等逐条显示）

## 真机验证（OnePlus 16 / PYB110 / SukiSU）
- 连续运行 700+ 秒未重启，模块 Live
- `/system/bin/su` 生成，`su -c 'id -u'` = 0
- App root 诊断：应用进程 root 已生效
- 管理器显示 MT 管理器超级用户已开启，MT 内 uid=0(root)
- oplus_secure_guard_new / oplus_secure_common 已卸载
- 无 onekey/su_compat 挂载

## 关于“还会不会卡住”
- 之前你反复遇到的卡死/重启是上面的**必发问题**，不是偶发；v2.5.22 已修复
- 上游 README 也明确说明：CVE-2026-64560 是竞态 UAF，**任何一次运行仍有小概率内核 panic / 重启**，这是漏洞本身风险，无法保证 0
- v2.5.22 已把可控的必发因素去掉；偶发内核竞态只能通过重试恢复
