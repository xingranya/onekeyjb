# 一加16提权越狱 v2.5.2 更新日志（su 通道修复）

**作者：星苒鸭 · github.com/xingranya · xran.uk**

## 先理清「应用调 su」到底靠什么
`Runtime.exec("su")` / 终端 `su` 正常路径：
1. 应用调用 PATH 里的 `/system/bin/su`
2. KernelSU 内核模块（LKM）的 **sucompat 内核钩子**接管这次 exec
3. 按该应用 UID 查管理器的授权名单
4. 已授权 → 给 root 凭证，执行 ksud 提供的 su wrapper

所以三个条件缺一不可：**LKM 已加载 + su wrapper 有效 + 管理器授权名单可写**。
ColorOS 17 的安全机制（`oplus_secure_guard` 等）会把这个"原生内核调用"拦截/干掉，
表现就是终端 `su: can't execute: Permission denied (126)`、管理器授权了应用也用不了。

## v2.5.2「su 通道修复」（等价 soft_reboot_core，但不需要装模块）
越狱收尾时以 root 执行完整修复链：
1. 卸载 `oplus_secure_guard` / `oplus_security_guard` 等 ColorOS 安全内核模块
2. 重装管理器 APK（刷新内核侧管理器绑定，授权名单写入依赖它）
3. **关键：`ksud soft-reboot` 重跑 late-load stage 脚本，重建 `/system/bin/su` 的 kernel file wrapper**
   - 不是只 `setprop ctl.restart zygote`（只重启 zygote 不会重建 su wrapper）
   - 失败才回退 restart zygote
4. 该修复集成在 run.sh 收尾里，以 root 执行；如果 shell 拿不到 root，会自动改用 KSU fd 方式重试

## 仍然不开默认 SU
- 「默认 SU 兼容」保持关闭，**不创建任何 su_compat / system_ext 挂载**，环境不暴露
- 修的是内核原生的 `/system/bin/su` 通道，不是 overlay
