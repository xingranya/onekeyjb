# 一加16提权越狱 v2.5.25 更新日志（修复官方/Next 管理器“未安装”）

**作者：星苒鸭 · github.com/xingranya · xran.uk**

## 根因（这次是代码层面的确定原因）
v2.5.24 日志已经能看到：
- 内核模块 Live、su 通道正常
- 但「管理器身份登记失败：com.rifsxd.ksunext (cert=998)」

进一步查 ksud 二进制后确认：
- **只有 SukiSU 的 ksud 有 `manager add` 子命令**
- 官方 KernelSU / KernelSU-Next / BakaSU 的 ksud **没有 `manager add`**，只有 `debug set-manager <apk>`，管理器主要靠 `ksud install` 自动识别
- 我们之前对所有管理器都调用 `manager add`，所以官方/Next/BakaSU 必然失败
- 登记失败后管理器拿不到内核通道，首页就显示「未安装 / 点击安装」，但 root 本身是正常的

## v2.5.25 修复
1. 按管理器类型分流登记：
   - SukiSU：`ksud manager add <pkg> <cert_size> <hash>` + set-enabled
   - 官方 / Next / BakaSU：`ksud debug set-manager <manager.apk>`
   - 失败会明确打日志，不再静默
2. **优先使用管理器 APK 自带的 libksud.so**（与管理器/LKM 版本严格匹配），取不到才退回内置 ksud
3. 软重启增加日志：`/data/local/tmp/onekey-softreboot.log`，记录 `ksud soft-reboot` 和 `setprop ctl.restart zygote` 的返回码，没重启时可以直接看原因
4. 管理器首次未连接时自动重试重启一次

## 验证方法
1. 装 v2.5.25，点「修复」
2. 等流程完成后打开对应管理器首页
3. 正常应显示内核版本/已安装，而不是「未安装」
4. 若仍显示未安装，把日志里这几行发我：
   - `debug set-manager 失败 rc=...: ...`
   - `管理器已通过 debug set-manager 登记`
   - `/data/local/tmp/onekey-softreboot.log` 内容
