# 一加16提权越狱 v2.5.0 更新日志

**作者：星苒鸭 · github.com/xingranya · xran.uk**

## ✅ 四个管理器全部按「配对版本」放行，不再因版本/签名不一致卡住
- 管理器版本与签名检查改为「只提示、不拦截」：
  - 以前 SukiSU 要求必须 v4.2.1、Next 要求签名匹配官方证书，版本/签名不同就直接停止
  - 现在只要装了对应管理器就继续越狱，LKM + ksud 已内置严格配对，管理器版本不同也能工作
- 四个管理器的推荐配对（仅提示）：
  | 管理器 | 推荐版本 | 对应内置内核/ksud |
  | --- | --- | --- |
  | KernelSU 官方 | v3.3.1 | ksu-base.ko + ksud 3.3.1 |
  | KernelSU-Next | v3.4.2 | ksu-base-next.ko + ksud 3.4.2 |
  | SukiSU Ultra | v4.2.1 | ksu-base-sukisu.ko（自定义 LKM，模块版 41027-5）|
  | BakaSU（原 ReSukiSU） | v4.2.0-rc3 (35235) | ksu-base-bakasu.ko + ksud 4.2.0-rc3 |
- 越狱日志新增「版本配对」一行：管理器版本 / 内核模块版本，一眼确认是否配对
- SukiSU 管理器显示 **[自定义]** 属正常（不是版本错误），不会再弹「内嵌 LKM 有可用更新」

## 🔄 继承 v2.4.9 的 ColorOS 17 安全机制修复
- 越狱后自动：卸载 oplus 安全内核模块 → 重装管理器 → 软重启用户态（ksud soft-reboot，失败回退 setprop ctl.restart zygote）
- 内核 LKM 保持加载，软重启后重新打开应用即可，不需要重新越狱
- 开关「越狱后软重启修复（ColorOS 17 安全机制）」默认开启

## 🛠️ 越狱链路（4 个管理器统一）
- 唯一工作目录 + 投放前建目录（无 Permission denied）
- grab.sh 动态目录（bl 抓包不再全空）
- 4 个 LKM 均补全本机完整 vermagic（finit_module 不再 EINVAL）
- 统一 perf_cred_sukisu 加载：只传 allow_shell=1（不传 bundled=1，避免内嵌 LKM 提示与授权异常）
- su -c 优先收尾、ksu_grant 兜底；su_compat 显式开启；管理器连接校验
