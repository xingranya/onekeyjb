# 165 · 一键越狱脚本（onekey_jailbreak.sh）说明与验证

日期：2026-10-19
脚本：`onekey_jailbreak.sh`（仓库根目录，637 行 bash，仅依赖 adb + 带 pyelftools 的 python）
目标：把 [docs/164](164-越狱成功-OnePlus16-20261019.md) 手动跑通的整条链固化成**一条命令**。
适用：OnePlus 16 / PYB110 / ColorOS 17.0.0.155 / 内核 6.18.21-android17-5-gf957accaf563-ab15926176-4k；仅本人/授权设备。

## 0. 一句话

设备**重启后**（LKM/SELinux permissive/adb root 全消失的状态）直接执行：

```bash
./onekey_jailbreak.sh
```

它会：取当前 boot slide → 按 slide 重打 LKM（cred+noenforce+vermagic+syms）→ 推送 → SELinux permissive → 泄漏 cred → 零写 fsuid → 写 cap_effective → finit_module 加载 KernelSU-Next（越狱/late-load）→ GRANT_ROOT → ksud install → 打开 adb_root → 重启 adbd → 验收为 `uid=0`。

## 1. 阶段划分

| 阶段 | 内容 | 是否会动内核 | 自动跳过条件 |
|---|---|---|---|
| 0 | 环境/依赖/设备检查、读电量、记录 uptime | 否 | — |
| 1 | `grab_blocked.sh` + `slide_now.py` 取当前 boot KASLR slide（锚定法校验） | 否 | `--slide` 指定 |
| 2 | `mk_kallsyms` → cred 补丁 → noenforce 补丁 → vermagic → 符号补丁 | 否 | — |
| 3 | 推送 perf_cred / v36 / v42 / ksud342 / ksu_grant / root_stage / ko | 否 | — |
| 4 | `v36` 零写 `selinux_state-7` → Permissive | 是（零写） | 已是 Permissive |
| 5 | `perf_cred` perf tracepoint 泄漏 cred | 只读 | `--cred` 指定 |
| 6 | `v36` 零写 `cred+0x20`（fsuid/fsgid=0） | 是（零写） | — |
| 7 | `v42` 两阶段写 `cap_bset/cap_effective` → `finit_module` | 是（零写+加载模块） | 模块已在本次 boot 加载 |
| 8 | `ksu_grant`（GRANT_ROOT）→ `root_stage`（ksud install + adb_root + libadbroot + 重启 adbd） | 用户态 | — |
| 9 | 验收（id/su/getenforce/modules/ksud debug info）+ 刷新管理器 + 截图 + 清理漏洞进程 | 否 | — |

执行时每阶段打印 `========== Stage N/9 ... ==========`，全程 tee 到 `out/onekey/run-<时间>.log`，产物/状态在 `out/onekey/work/`。

## 2. 常用命令

```bash
./onekey_jailbreak.sh                    # 完整一键越狱（重启后跑）
./onekey_jailbreak.sh --yes              # 非交互确认
./onekey_jailbreak.sh --check            # 只体检，不做任何利用（安全）
./onekey_jailbreak.sh --slide-only       # 只抓/反推当前 boot 的 slide（安全）
./onekey_jailbreak.sh --build-only --slide 0x28baa00000   # 只重打 ko（安全）
./onekey_jailbreak.sh --verify-only      # 只验收 + 刷新管理器 UI（安全）
./onekey_jailbreak.sh --to 3             # 只跑 0-3（slide+打ko+部署，不动内核）
./onekey_jailbreak.sh --from 6           # 从阶段 6 续跑（配合 out/onekey/work/state.env）
./onekey_jailbreak.sh --force            # 强制重跑（即使检测到模块已加载 / 未锚定 slide）
```

可调参数：`--serial`、`--cred`、`--attempts-perm`（默认 120）、`--attempts-fsuid`（150）、`--attempts-caps`（150）、
`--timeout-perm`（1500s）、`--timeout-fsuid`（1800s）、`--timeout-caps`（2400s）、`--no-shot`、`--keep`。

## 3. 脚本里的安全/健壮性设计

- **每阶段判据严格**：permissive 要 `getenforce=Permissive`；fsuid 要 `STEP_OK` + `LAYOUT_DONE`；caps 要 `MODULE_LOADED` 且 `/proc/modules` 有 `kernelsu`；root 要 `id` 含 `uid=0(root)`，否则直接失败。
- **重启检测**：记录启动 uptime，轮询时若 uptime 明显回退（< 基线-60s）立即终止并提示重跑（防用上一个 boot 的地址继续写）。
- **地址安全**：全新完整运行会**忽略**旧的 slide/cred（防止重启后误用上一个 boot 的地址）；只有在 `--from N`（续跑）时才读 `state.env`；stage6/7 会检查 `perf_cred` 仍存活，防止写已释放的 cred。
- **slide 可信度**：默认要求 `slide_now.py` 的"锚定法"多组交叉验证通过，否则拒绝继续（`--force` 才放行）。
- **失败清理**：退出时 kill 主机后台 adb 任务和设备上的 `t64560_*`/`perf_cred`（`--keep` 可保留），避免残留进程继续写内存。
- **adbd 重启重连**：stage8 后自动重新发现 adb 序列号并等待重连（最多 180s），不依赖原来的无线调试端口。
- **管理器陈旧的「未安装」**：stage9 自动 `am force-stop` + 重新打开管理器，避免旧的错误状态。
- 全程**不重启设备、不写任何分区**；只在 `/data/local/tmp` 和 `/data/adb` 放文件。

## 5. 重启后怎么用（推荐流程）

```bash
# 1) 设备重启、无线调试连上后
adb devices

# 2) 一条命令（约 10-40 分钟，取决于竞态命中速度；期间设备可能自动重启，脚本会报错，重跑即可）
./onekey_jailbreak.sh --yes

# 3) 成功后
adb shell id          # uid=0(root) ... context=u:r:ksu:s0
adb shell getenforce  # Permissive
```

## 6. 失败与恢复

- **某阶段未命中/超时**：脚本会打印设备侧日志尾部并退出。设备若 panic 自动重启，直接重跑脚本即可（脚本会重新取 slide）。
- **卡在 stage4**：多为竞态未命中或 cache 脏，重启后重跑；也可加大 `--attempts-perm` / `--timeout-perm`。
- **stage8 adb 没重连**：看设备屏幕是否提示无线调试；`root_stage.log` 在 `/data/local/tmp/`，其中 `LIBADBROOT_OK` / `install_rc=0` / `setprop_rc=0` 是判据。
- **想保留现场排查**：`--keep` 不杀漏洞进程；日志在 `out/onekey/run-*.log` 与 `out/onekey/work/`。

### 8.4 本轮修的一个通用 bug

`grab_blocked.sh` 依赖 `/sys/kernel/tracing/trace` 里残留的 `sched_blocked_reason` 文本行做 `%pS` 锚点；
perfetto 退出时会把事件 disable，冷启动后 trace 可能没有残留行 → `bl_text.txt` 为空、slide 只能走启发式。
现在 bash/PS 两个一键脚本都在 grab 之后**显式重新 enable 事件 + 打开 tracing_on + 用 forker 制造阻塞再抓一次文本**，
实测能稳定拿到几十~几百行锚点（本次 192 行），锚定法正常通过。
