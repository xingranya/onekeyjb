# 151 — ★「写-哪-哪」验证通过（攻击者指定地址 + 指定值，且不崩）

日期：2026-10-18 00:43
设备：M610BB / SM8950 / Android 17 / 内核 `6.18.21-android17-5-g1d099fcb35e0`，补丁级 2026-09-01
漏洞：CVE-2026-64560（`posix-cpu-timers` 非 leader exec 竞态 UAF），上游修于 6.18.41

## 0. 结果

```
PROBE_SET        attempt=2   node=0xffffff89f44e5be0  base=0xffffff89f44e4000
WRITE_CONFIRMED  attempt=42  addr=0xffffff89f44e4200  val=0  (was 0x41)
```

- `base` 是**从上一轮泄漏里算出来的**页基址（`node & ~0x1fff`），不是常量；
- `addr = base + 0x200` 是**我们指定的地址**；
- 值 `0` 是**我们指定的**（伪造节点的 `rb_right`）；
- 观测方式：该页是我们 socket 的数据页，用 `MSG_PEEK` 保留，**字节从模板的 0x41 变成 0**；
- 整个过程 **没有 panic**（设备 uptime 连续，最新 kpanic 仍是 00:34:20 的上一次实验）。

⇒ 至此拿到完整的一条「零特权 → UAF → 页接管 → **攻击者指定的 8 字节写**」链路。

## 1. 两个必须同时满足的约束（今晚踩出来的）

第一次做这件事（v25/v26）都崩了，原因逐条查清：

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | v25 崩 | `parent` 非 NULL 时 `rb_next(node)` 返回 `parent`，`rb_erase_cached` 把它写进 `root->rb_leftmost`；随后 `cleanup_timers` 把 `parent` 当成下一个节点继续删 → 那是个"半成品"地址 | 让 `parent` 本身也是**合法假节点**：在其 `__rb_parent_color`（页偏移 0x1f8）预置 0 |
| 2 | v26 仍崩 | 辅助节点的 `rb_left` 还是 `0x41…` 填充 ⇒ `__rb_erase_augmented` 走「只有左孩子」分支，执行 `tmp->__rb_parent_color = pc` 对 `0x41…` 写入 | 辅助节点 `rb_left`（页偏移 0x208）也置 0 |

最终可用的页布局（相对 8KB 页）：

| 偏移 | 内容 | 作用 |
|---|---|---|
| `k*0x180 + 0xe0` | 伪造 `k_itimer.it.cpu.node`（`parent_color`/`right`/`left`/`expires`） | 被内核遍历到的悬空节点 |
| `0x1f8` | `0` | 辅助假节点的 `__rb_parent_color`（parent NULL、红） |
| `0x200` | `0x41…`（初始），被写成 `0` | **写入目标**（`parent->rb_right`），也是观测点 |
| `0x208` | `0` | 辅助假节点的 `rb_left`，必须为 0 |

## 3. 还差的那一步（如实说明）

写原语有了，但**目标地址没有**。要写 `cred` 需要先知道 `task_struct` 或 `cred` 的地址，
这需要一个「读」；我们目前只有「写」。

几条候选，按可行性排：

1. **`collect_posix_cputimers` 的 `current` 写**：反汇编确认它会把 `current`（`task_struct *`）
   写到 `node + 0x48`。但它只在"计时器真的到点"时执行，而这条路径对**未落地**的轮次会把
   已被 cache 复用的悬空节点也走一遍 ⇒ 直接崩（v24 实测：45 次 attempt 后 kpanic）。
   要安全使用，必须**先确认该轮已落地**，而确认手段（退出路径）又会把节点摘掉 —— 时序上互斥。
2. **参考实现的 `miscdevice` 桥**：伪造 `miscdevice`（classes=11、stride 0x58）挂进 `misc_list`，
   `.fops` 指向页内伪造表 ⇒ 任意读写。但这要求 **内核镜像基址**（`misc_list` 是静态符号），
   而 `kptr_restrict` + SELinux 让我们读不到 `/proc/kallsyms`、`/proc/iomem`，
   `dmesg`（512KB 环形缓冲）里也没有 `Kernel Offset`。
3. **把写变成读**：用 `__rb_change_child` 的 `parent->rb_left == node` 分支做 1 bit 比较，
   但每次查询要一次落地（3%/6s），不实用。

⇒ 结论：**完整 root 链的真正缺口是「一个内核静态地址（slide）或一个 `cred`/`task` 堆地址」**，
其余原语已经齐备。
