# 一加16提权越狱 v2.5.1 更新日志（漏洞链整体切换）

**作者：星苒鸭 · github.com/xingranya · xran.uk**

## 🔁 漏洞链换成上游验证过的那套（和"能用的那个人"完全一致）
之前一直沿用的是 v2.3.3 的链路（t64560_v36 + perf_cred + t64560_v42）。
它在我们的机器上能加载模块、管理器也显示"工作中"，但**授权始终异常**——问题就出在这条链留下的内核状态上。

v2.5.1 起直接改用上游 run.sh 全链路：
- `take_slide.sh` 抓 slide
- `prep_solve` 解 slide
- `prep_patch` 按本机 uname 打符号 + vermagic 补丁
- `t64560_v36` → SELinux Permissive
- `t64560_loader2` → cred 泄漏
- `t64560_w2` → cred 写入 + finit_module 加载 LKM（allow_shell=1）
- 收尾：ksud install → crown → 管理器重启

4 个管理器只需切换 `PYB110_MANAGER`（kernelsu / next / bakasu / sukisu），
LKM 与 ksud 仍是内置严格配对的那四套（官方 3.3.1 / Next 3.4.2 / BakaSU 4.2.0-rc3 / SukiSU 4.2.1）。

## 其他保留
- 管理器版本/签名只提示不拦截（不因版本不一致停止）
- 唯一工作目录、投放前建目录（不再 Permission denied）
- ColorOS 17 安全机制修复：越狱后卸载 oplus 安全内核模块 + 软重启用户态（LKM 保持加载）
  - 改为独立脚本执行，**不再重装管理器**，避免把授权状态重置
- 关于页「导出设备诊断」保留

## 包体
- 移除旧链路（v36/v42/perf_cred/旧 syms 等）约 9MB，加入上游链路约 16MB，APK 27.4MB

## 刷完状态
- 日志应依次出现：`SLIDE → PATCH → SELINUX_OK → CRED → MODULE_LOADED → DONE`
- 管理器 `[LKM] [自定义] [越狱模式]`，授权应用后重开应用即可
