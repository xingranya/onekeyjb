# 一加16提权越狱 v2.5.13 更新日志（真机实测 + 安全模块修复）

**作者：星苒鸭 · github.com/xingranya · xran.uk**

## 真机验证结果（一加16 / PYB110 / SukiSU）
- 完整越狱跑通：采集 → 校准 → 内核补丁 → SELinux Permissive → cred → 加载内核模块（Live）→ 管理器初始化 → 软重启恢复
- 管理器显示「工作中 [越狱模式]」，超级用户列表正常，本应用授权状态为 ROOT
- Root 诊断实测：**应用进程 su 已生效**（绝对路径与 PATH/libsu 两种方式都通过）
- 无 onekey / su_compat 挂载，环境保持干净

## 本版修复
1. **安全模块名称变化导致没卸掉**：ColorOS 17 实际加载的是
   `oplus_secure_guard_new` / `oplus_secure_common`，旧列表只匹配 `oplus_secure_guard` 所以一直没生效
   - 改为按 `^oplus_secure` 动态匹配并卸载
   - 真机确认：修复后两个模块已从 /proc/modules 消失
2. **回退加载链时误用了旧 grab.sh**：写死 /data/local/tmp/onekey，导致 bl 抓包全空（真机第一次测试就复现）
   - 恢复为动态工作目录版本
3. **Root 诊断细分**：绝对路径 / PATH(libsu) / sh+绝对 / sh+PATH / 兼容入口 五项分别显示，
   不再用“1/4 项”让人误判；应用进程 root 生效即为授权成功

## 说明：终端类 shell 的 su
- `sh -c su`、终端内直接敲 su 仍会被系统策略拒绝（当前 SukiSU 越狱模式 + ColorOS 的限制）
- 使用 libsu / 绝对路径调用 su 的应用（绝大多数 root 工具）不受影响
- 如果确有终端类应用必须用 PATH su，只能开启「默认 SU 兼容」用兼容层兜底（会多一个挂载，可能被检测）
