# 一加16提权越狱 v2.5.3 更新日志（修复顺序 + 链路复查）

**作者：星苒鸭 · github.com/xingranya · xran.uk**

## ✅ 你说的顺序是对的：安全组件修复不能在越狱后立刻做
v2.5.2 的修复是越狱收尾里"立刻执行"，此时：
- 管理器刚被重启，还没连上内核（ksu fd 未建立）
- ksud 刚安装，late-load 状态还没稳定
- shell 的 su 通道可能还没就绪
→ 于是 `su -c 修复脚本` 直接失败，自动修复形同失效

## v2.5.3 改成严格先后顺序 + 后台排队
1. 越狱链路跑完（run.sh 的 install / crown / 管理器重启）
2. **排队**：不阻塞越狱，后台启动 `su_repair_launch.sh`
3. **等 shell su 就绪**（每 2 秒探测，最多 60 秒）
4. 修复脚本再**等管理器连上内核 + ksud 就绪**（最多 120 秒），再等 5 秒让管理器完成初始化
5. 然后才：卸载 `oplus_secure_guard` 等安全内核模块 → 重装管理器 → `ksud soft-reboot` 重建 `/system/bin/su`
6. 修复完成自动软重启（LKM 保持加载，不用重新越狱）

这样越狱主体不被修复拖死，日志也能先保存；修复失败也不会影响已加载的模块。

## 🔍 越狱链路复查发现并修掉的问题
1. **残留进程**：上次运行留下的 `trace_pipe_raw` / `t64560_w2` / `loader2` / `prep_*` 会干扰 slide 抓取 → 越狱前统一清理
2. **run.sh 收尾立刻修**：见上，改为后台排队
3. **修复失败无兜底**：run.sh 里排队失败时，应用会用 KSU fd 方式按同样顺序再试一次
4. **诊断补强**：导出诊断新增 `/data/local/tmp/su_repair.log`、su_repair_launch.log、oplus 模块列表、ksud 版本
