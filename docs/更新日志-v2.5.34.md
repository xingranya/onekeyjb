# 一加16提权越狱 v2.5.34 更新日志（修复 KSU/Next 管理器未安装 + 截屏异常 + 安全组件恢复）

作者：星苒鸭 · github.com/xingranya · xran.uk

## 1. 官方 KernelSU / KernelSU-Next 管理器“未安装”——已找到根因并修复

真机抓内核日志确认：
- 管理器识别依赖内核的 Crowning manager 流程
- 内核监听 /data/system/packages.list 的重命名事件；只改权限/chmod 不会触发
- 触发后内核打印 KernelSU: Crowning manager: uid=10365，管理器立刻显示“工作中”

之前为了避开 92% 卡死删掉了 crown，导致官方/Next 永远无法被管理器识别（SukiSU 有自己的 manager add，所以正常）。

v2.5.34 恢复 crown，但改成安全版：
- 仅对官方 / Next / BakaSU 执行
- mv 全程包在 timeout 10 里
- trap 里兜底把 packages.list.onekey 移回，异常也不会留下半截文件
- 真机验证：官方 KernelSU 管理器从“未安装”变为“工作中”，内核版本 32680-5 正确显示

## 2. 截屏功能失效

原因有两个：
- 之前会 rmmod oplus_secure_guard_new / oplus_secure_common，这些模块参与系统安全/截屏相关路径
- v2.5.20 时期曾批量停用 com.coloros.securityguard / com.oplus.safecenter，后续版本只恢复了 exsystemservice，导致它们一直处于禁用状态

v2.5.34：
- 不再 rmmod 任何 oplus_secure 模块
- 收尾和 trap 里统一恢复 com.oplus.exsystemservice、com.coloros.securityguard、com.oplus.safecenter
- 真机验证：修复后 pm list packages -d 中这三个包都不再是禁用状态

## 3. 自动重启后掉 root

- 当前方案是 late-load，root 只在本次开机内有效；真正重启后一定掉 root，需要重新越狱，这是机制决定的
- 运行中自动重启，最可能是 ColorOS 安全组件检测到内核模块后触发；也可能是旧版本残留的安全组件被禁用导致系统异常
- v2.5.34 已恢复所有安全组件、移除 rmmod，减少这两类副作用
- 建议观察：如果更新后仍出现运行一段时间自动重启，请发我 /data/local/tmp/onekey-last.log 和重启前的 logcat
