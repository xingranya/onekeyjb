## 3. 用户态收尾：从模块到 adb root（本次新增的关键发现）

### 3.1 最短路径：GRANT_ROOT ioctl（无需再跑 UAF）

allow_shell=1 时，**uid 2000 的 shell 自己就能申请 root**。KernelSU-Next v3.4.2 协议：

1. `reboot(0xDEADBEEF, 0xCAFEBABE, 0, &fd)` —— 内核 reboot kprobe 把 anon ksu driver fd 装进当前进程；
2. `ioctl(fd, KSU_IOCTL_GRANT_ROOT /*0x4b01*/, NULL)` —— 权限检查 `allowed_for_su()`，因 `allow_shell=1` 放行 → `escape_with_root_profile()`；
3. 进程变成 `uid=0, context=u:r:ksu:s0`，可 exec 任意 root 脚本。

实现：`src/ksu/ksu_grant.c` → `bin/ksu_grant`（aarch64 freestanding，~132 KB）。
实测输出：
```
reboot_rc=-1 fd=3
grant_root_rc=0
uid=0 euid=0
```

### 3.2 ksud 用户态安装（root 下执行）

`src/ksu/root_stage.sh`（由 ksu_grant 以 root exec）：
```bash
/data/local/tmp/ksud342 install       # rc=0 → /data/adb/ksud + /data/adb/ksu/bin/{ksud,busybox,bootctl,resetprop,su}
/data/adb/ksud feature set adb_root 1 # rc=0
```

features：su_compat(0)、kernel_umount(1)、**adb_root(3)=1**、avc_spoof 均为 ENABLED。

### 3.3 adb root（最终一步）

`src/ksu/adbroot_stage.sh`：
```bash
# 管理器 APK 里带 libadbroot.so
cp /data/app/*/com.rifsxd.ksunext*/lib/arm64/libadbroot.so /data/adb/ksu/lib/libadbroot.so
chown root:root ...; chmod 644 ...

```
adbd 被 init 重新 exec 时，adb_root 的 execve hook 设置
`LD_PRELOAD=/data/adb/ksu/lib/libadbroot.so` 并 `escape_to_root_for_adb_root()`：
```
KernelSU: escape to root for adb
```
adbd 以 root 运行，adbd 重启后 adb 自动重连（同 serial），**无需重新配对**。
