# 06 · 构建与发布

## 环境

| 项 | 要求 | 说明 |
| --- | --- | --- |
| JDK | **21**（`/opt/homebrew/opt/openjdk@21`） | Stellar API 的 class 文件版本是 65.0，JDK 17 直接编译会报"程序包 Stellar 不存在 / 类文件具有错误的版本 65.0" |
| Android SDK | compileSdk 37、build-tools 37.0.0 | `compileSdk { version = release(37) } ` |
| Gradle | 9.7.1（wrapper 自带） | 不需要本机装 |
| minSdk / targetSdk | 33 / 37 | |

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@21
export PATH="$JAVA_HOME/bin:$PATH"
cd merged-app
./gradlew assembleRelease
```

产物：`merged-app/app/build/outputs/apk/release/app-release.apk`。

## 签名

`merged-app/keystore.properties`（不入库）指向证书文件，模板见 `keystore.properties.example`。
debug 与 release 共用同一把密钥，保证 debug 包也能覆盖安装。

签名证书 SHA-256 必须等于 `a023f95cd5c4aa99d64444215c9bd605e17d90c3140fa97e1fefe1c537be487e`，
这是 `SecurityCheck` 的硬编码信任根——换密钥出的包能装，但一点"一键越狱"就会被签名校验拒绝。

## 版本号

改 `merged-app/app/build.gradle.kts`：

```kotlin
versionCode = 164
versionName = "2.17.16"
```

`versionCode` 只增不减；界面顶栏会显示 `v<versionName> · #<versionCode>`，方便对版本。

## 发版流程

1. 改版本号 → `assembleRelease`；
2. `cp app-release.apk dist/OneKeyJB-v<版本>.apk`，`shasum -a 256` 记下体积与哈希；
3. 生成 `update.json`（含 `publishedAt`、`size`、`sha256`、`versions[]`）；
4. 需要时重发云端模块与 `cloud-catalog.json`（见 04）；
5. 上传到 CNB `update` 标签，再下载回来复核哈希；
6. 同步仓库 `artifacts/` 与 `knowledge/`。

## CNB 上传接口

```python
# 1) 申请上传地址
POST https://api.cnb.cool/xingranya/onekeyjb/-/releases/<RELEASE_ID>/asset-upload-url
     {"asset_name": "OneKeyJB-latest.apk", "size": 42839435}
# 2) PUT 到返回的 upload_url
# 3) POST 返回的 verify_url 确认
```

Token 在 `~/.cnb/token`，形如 `{"access_token": "..."}`，请求头 `Authorization: Bearer <token>`。
同名资产会被覆盖，上传完务必重新下载一次比对 `sha256`——CDN 有缓存，偶尔要等几秒。

## 常见构建问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `程序包 Stellar 不存在` / `类文件具有错误的版本 65.0` | 用了 JDK 17 | 切到 JDK 21 再编译 |
| `无法访问 StellarRemoteProcess` | 同上 | 同上 |
| 安装后点越狱立刻"签名校验失败" | 换过签名密钥 | 用项目密钥重签 |
| 装不上（INSTALL_FAILED_UPDATE_INCOMPATIBLE） | 与已装包签名不同 | 卸载旧包或换回原密钥 |
